# PRD: Агент для написания кода с SGR-схемами

## 1. Обзор продукта

### 1.1 Название продукта
**SGR-CodeAgent** - многоролевой агент для генерации высококачественного кода с использованием структурированных схем SGR (Structured Generation with Reasoning) в рамках экосистемы ShinkaEvolve.

### 1.2 Краткое описание
SGR-CodeAgent представляет собой автономную систему, которая использует пять специализированных ролей для создания, тестирования и интеграции программного кода. Агент интегрируется с фреймворком ShinkaEvolve для эволюционного улучшения своих решений и использует SGR-схемы (Pydantic-модели) для обеспечения типобезопасности, валидации и структурированного вывода.

### 1.3 Цели продукта
- **Автоматизация полного цикла разработки**: от анализа требований до развертывания
- **Обеспечение качества кода**: через многоуровневое тестирование и ревью
- **Интеграция с ShinkaEvolve**: для эволюционного улучшения архитектуры агента
- **Использование SGR**: для типобезопасного и структурированного подхода к генерации кода

### 1.4 Ключевые особенности
- Многоролевая архитектура с пятью специализированными агентами
- Интеграция с SGR-схемами для структурированного вывода
- Эволюционное улучшение через ShinkaEvolve
- Автоматическое тестирование и валидация
- Поддержка различных языков программирования и фреймворков

## 3. Функциональные требования

### 3.1 Архитектор (Architect) - Routing Pattern
**Роль**: Анализ требований и выбор оптимальной архитектуры

**Функции**:
- Анализ пользовательских требований и технических ограничений
- Выбор технологического стека (язык, фреймворки, библиотеки)
- Определение общей архитектуры приложения
- Оценка сложности и определение приоритетных компонентов

**SGR-схема**:
```python
class ArchitectureSpec(BaseModel):
    tech_stack: Dict[str, str]
    component_structure: List[Component]
    integration_points: List[IntegrationPoint]
    deployment_strategy: DeploymentConfig
    risk_assessment: RiskAnalysis
```

### 3.2 Программист (Coder) - Cycle Pattern
**Роль**: Генерация и итеративное улучшение кода

**Функции**:
- Создание плана разработки на основе архитектуры
- Генерация кода с использованием SGR-схем
- Итеративное улучшение (план → код → рефакторинг)
- Обеспечение соответствия стандартам кодирования

**SGR-схема**:
```python
class CodeGenerationRequest(BaseModel):
    component_name: str
    functionality: str
    dependencies: List[str]
    interfaces: List[InterfaceSpec]
    test_requirements: TestSpec
```

### 3.3 Тестировщик (Tester) - Cascade Pattern
**Роль**: Создание и выполнение тестов

**Функции**:
- Разработка плана тестирования
- Генерация unit-тестов
- Создание интеграционных тестов
- Генерация отчетов о покрытии и результатах

**SGR-схема**:
```python
class TestSuite(BaseModel):
    test_plan: List[TestCase]
    test_data: Dict[str, Any]
    expected_results: Dict[str, Any]
    coverage_requirements: CoverageSpec
```

### 3.4 Рецензент (Reviewer) - Routing Pattern
**Роль**: Анализ качества и стиля кода

**Функции**:
- Статический анализ кода
- Проверка стиля кодирования
- Анализ комментариев и документации
- Предоставление рекомендаций по улучшению

**SGR-схема**:
```python
class CodeReview(BaseModel):
    style_issues: List[StyleIssue]
    security_concerns: List[SecurityIssue]
    performance_issues: List[PerformanceIssue]
    documentation_gaps: List[DocumentationGap]
    overall_score: float
```

### 3.5 Интегратор (Integrator) - Сборка и развертывание
**Роль**: Финальная сборка и развертывание

**Функции**:
- Сборка проекта из компонентов
- Настройка конфигурации
- Создание CLI и API интерфейсов
- Подготовка к развертыванию

**SGR-схема**:
```python
class IntegrationSpec(BaseModel):
    build_config: BuildConfiguration
    deployment_config: DeploymentConfiguration
    cli_interface: CLIInterface
    api_endpoints: List[APIEndpoint]
```

## 4. Технические требования

### 4.1 Интеграция с ShinkaEvolve
- Использование EVOLVE-BLOCK для мутируемых частей
- Реализация функций `run_experiment()` и `evaluate.py`
- Поддержка novelty rejection и bandit selection

### 4.2 SGR-схемы
- Все выходы агентов должны быть Pydantic-моделями
- Использование `chat.completions.parse()` для структурированного вывода
- Валидация схем на уровне типов

### 4.3 LLM интеграция
- Поддержка OpenAI, Anthropic, Google models
- Настраиваемые параметры (temperature, max_tokens)
- Fallback mechanisms для отказоустойчивости

### 4.4 Система тестирования
- Автоматическая генерация и выполнение тестов
- Поддержка pytest, unittest
- Анализ покрытия кода

### 5.2 Паттерны взаимодействия

#### Routing Pattern (Архитектор, Рецензент)
- **Вход**: Запрос пользователя
- **Обработка**: Маршрутизация к соответствующему специалисту
- **Выход**: Решение или делегирование

#### Cycle Pattern (Программист)
- **Итеративный процесс**:
  1. Планирование → Генерация кода
  2. Тестирование → Рефакторинг
  3. Итерация до достижения качества

#### Cascade Pattern (Тестировщик)
- **Последовательный процесс**:
  1. План тестирования
  2. Unit-тесты → Интеграционные тесты
  3. Отчет о результатах

2. Архитектор выбирает стек (React + FastAPI)
3. Программист генерирует компоненты
4. Тестировщик создает тесты
5. Рецензент проверяет качество
6. Интегратор собирает и развертывает

### 6.2 Сценарий эволюции: Улучшение существующего кода
1. Загрузка существующего проекта
2. ShinkaEvolve мутирует архитектуру агента
3. Улучшенный агент генерирует лучший код
4. Цикл продолжается до достижения оптимума

## 9. Риски и ограничения

### 9.1 Технические риски
- **Сложность SGR-схем**: Могут быть слишком ограничивающими
- **Зависимость от LLM**: Качество зависит от внешних API
- **Интеграция с ShinkaEvolve**: Сложность настройки эволюционных параметров

### 9.2 Бизнес-риски
- **Стоимость API**: Высокие затраты на LLM-вызовы
- **Конкуренция**: Аналогичные инструменты (Cursor, GitHub Copilot)
- **Адаптация**: Пользователям нужно время на изучение

### 9.3 Стратегии минимизации
- **Fallback mechanisms**: Локальные модели для снижения затрат
- **Кеширование**: Повторное использование успешных паттернов
- **Гибкая настройка**: Параметры для разных бюджетов
