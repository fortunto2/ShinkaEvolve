# PRD: Стартап-Агент для генерации продуктов на основе трендов

## 1. Обзор продукта

### 1.1 Название продукта
**IndieForge Agent** - AI-powered фабрика инди-стартапов по методологии Питера Левелса для создания простых продуктов, решающих одну конкретную боль, с быстрым запуском и монетизацией через Stripe.

### 1.2 Краткое описание
IndieForge Agent - это AI-фабрика для инди-хакеров по созданию простых, фокусированных продуктов. Каждый продукт решает ровно одну боль, создается быстро (дни/недели), монетизируется через Stripe и доступен бесплатно если не затратно. Агент находит нишевые проблемы, генерирует минималистичные решения и создает готовые к запуску продукты по принципу "12 стартапов за 12 месяцев".

### 1.3 Цели продукта
- **Поиск простых болей**: Находить конкретные проблемы, которые можно решить одним продуктом
- **Генерация минималистичных идей**: 1 продукт = 1 функция, решающая 1 боль
- **Быстрое создание**: Готовый продукт за дни/недели, а не месяцы
- **Freemium монетизация**: Бесплатно если не затратно + Stripe для премиум функций
- **Массовое производство**: Создавать множество продуктов по принципу "12 за 12 месяцев"

### 1.4 Ключевые особенности
- **Поиск простых болей**: Находить конкретные проблемы из Reddit/HackerNews
- **Минималистичные продукты**: 1 продукт = 1 функция для решения 1 боли
- **Быстрое создание**: Готовый MVP за 1-2 дня с автогенерацией кода
- **Freemium модель**: Бесплатно если не затратно + Stripe для премиум
- **Массовое производство**: Генерировать идеи для 12+ продуктов в месяц
- **Унифицированный стек**: Python/FastAPI + React/Next.js + Cloudflare
- **Stripe интеграция**: Готовая монетизация для премиум функций

## 3. Функциональные требования

### 3.1 Модуль мониторинга трендов (TrendMonitor)
**Роль**: Сбор и анализ данных из социальных платформ

**Функции**:
- Мониторинг subreddit'ов по заданным тематикам
- Анализ популярных постов и комментариев
- Отслеживание трендов в LinkedIn и других профессиональных сетях
- Интеграция с Google Trends API
- Определение emerging трендов и паттернов

**SGR-схема**:
```python
class TrendData(BaseModel):
    platform: str
    topic: str
    trend_score: float
    growth_rate: float
    related_keywords: List[str]
    sentiment_analysis: Dict[str, float]
    demographic_data: Dict[str, Any]
    timestamp: datetime
```

### 3.2 Модуль генерации идей (IdeaGenerator)
**Роль**: Поиск простых болей для минималистичных продуктов

**Функции**:
- Поиск конкретных проблем из Reddit/HackerNews постов
- Генерация идей продуктов, решающих ровно 1 проблему
- Оценка простоты реализации (MVP за 1-2 дня)
- Предложение freemium монетизации
- Анализ потенциала для indie-хакера (одиночки)
- Поиск "low-hanging fruits" - простых побед

**SGR-схема**:
```python
class SimpleProductIdea(BaseModel):
    problem_statement: str        # Конкретная боль из реального поста
    simple_solution: str          # 1 функция, решающая эту боль
    target_audience: str          # Кто именно страдает от этой боли
    mvp_complexity: str           # "1 day", "3 days", "1 week"
    freemium_model: str           # Как монетизировать премиум
    competition_level: str        # "None", "Low", "Medium"
    launch_effort: str            # Оценка усилий для запуска
    stripe_integration: bool      # Нужен ли Stripe
```

### 3.3 Модуль глубокого исследования (DeepResearch)
**Роль**: Комплексный анализ рынка и конкурентов

**Функции**:
- Автоматизированный поиск информации в интернете
- Анализ конкурентов и их продуктов
- Оценка рыночного потенциала
- Поиск патентов и интеллектуальной собственности
- Анализ регуляторных ограничений

**SGR-схема**:
```python
class ResearchReport(BaseModel):
    competitors: List[CompetitorAnalysis]

    technology_landscape: Dict[str, Any]

```

### 3.4 Модуль маркетингового анализа (MarketingResearch)
**Роль**: SEO-анализ, контент-стратегия и маркетинг в соцсетях

**Функции**:
- Анализ поисковой выдачи и определение нишевых возможностей
- Исследование конкурентов в SEO и их контент-стратегий
- Определение ключевых слов с низкой конкуренцией
- Планирование контент-стратегии (видео, посты, статьи)
- Анализ платформ: YouTube, TikTok, LinkedIn, Reddit
- Определение ICP среди контент-креаторов и солопренеров

**SGR-схема**:

### 3.5 Модуль аналитики (Analytics)
**Роль**: Анализ реальных рыночных данных и SEO-метрик

**Функции**:
- Поиск реальных данных о размере ниши через SimilarWeb, SEMrush, Ahrefs
- Анализ поискового спроса через Google Keyword Planner, Ubersuggest
- Оценка конкуренции в поисковой выдаче (SERP analysis)
- Анализ трафика конкурентов и их контент-стратегий
- Расчет потенциального трафика для новой ниши
- Определение монетизации через affiliate, курсы, сервисы

**SGR-схема**:
```python
class NicheAnalytics(BaseModel):
    niche_size_data: Dict[str, Any]  # Реальные данные из SimilarWeb
    search_volume: Dict[str, int]   # Объем поиска по ключевым словам

```

### 3.6 Модуль генерации PRD (PRDGenerator)
**Роль**: Создание MVP-спецификаций для быстрого запуска

**Функции**:
- Спецификация ровно 1 ключевой функции
- Простая архитектура для быстрого развертывания
- Freemium модель с Stripe интеграцией
- Минимальный UI/UX для валидации идеи
- План запуска за 1-2 дня

## 4. Технические требования

### 4.1 Интеграция с внешними источниками
- **Reddit/HackerNews API**: Для поиска реальных болей и проблем
- **Stripe API**: Для freemium монетизации и управления подписками
- **Cloudflare**: Для развертывания и CDN (бесплатный тариф)
- **Vercel/Netlify**: Для быстрого развертывания фронтенда
- **Supabase/PostgreSQL**: Для простого бэкенда (бесплатные тарифы)

### 4.2 SGR-схемы и валидация
- Все модули используют Pydantic-модели для структурированного вывода
- Автоматическая валидация на уровне типов
- Обратная связь для улучшения схем
- Версионирование схем для совместимости

### 4.3 Интеграция с ShinkaEvolve
- Модульная архитектура позволяет мутировать отдельные компоненты
- EVOLVE-BLOCK для каждого модуля
- Адаптивная эволюция на основе фитнес-функции
- Поддержка novelty rejection для избежания повторяющихся решений

### 4.4 Конфигурируемый технологический стек
- **Backend**: Python/FastAPI
- **Frontend**: React/Next.js
- **База данных**: PostgreSQL, MongoDB, Redis
- **Облачная инфраструктура**: Cloudflare (Pages, Workers, D1, KV)
- **Мультиязычная поддержка**: i18next, Next.js internationalization
- **CDN и оптимизация**: Cloudflare Images, Stream для видео

## 6. Пользовательские сценарии

### 6.1 Сценарий инди-хакера: 12 продуктов за 12 месяцев
1. Инди-хакер запускает агент с запросом "найди простые боли"
2. IdeaGenerator находит 10+ конкретных проблем из Reddit/HackerNews
3. Для каждой идеи генерируется SimpleProductIdea с 1 функцией
4. PRDGenerator создает MVP-спецификацию для самого простого продукта
5. Агент автогенерирует код и развертывает на Cloudflare
6. Продукт запускается с freemium моделью через Stripe
7. Процесс повторяется еженедельно для следующего продукта

### 6.2 Сценарий быстрого MVP: 1 продукт за 2 дня
1. Находится конкретная боль: "Разработчики тратят время на поиск API документации"
2. Генерируется идея: "One-click API documentation finder"
3. Создается спецификация с 1 функцией и freemium моделью
4. Автогенерация кода: FastAPI backend + React frontend
5. Развертывание на Cloudflare Pages за 1 день
6. Интеграция Stripe для премиум функций
7. Запуск и валидация идеи

### 6.3 Сценарий эволюции: Улучшение генерации идей
1. ShinkaEvolve мутирует модули для поиска более простых болей
2. Улучшенная версия фокусируется на "low-hanging fruits"
3. Система тестирует разные подходы к Stripe интеграции
4. Лучшие шаблоны продуктов сохраняются для повторного использования

- **Freemium потенциал**: Возможность монетизации премиум функций
- **Масштабируемость**: Легкость создания похожих продуктов

### 7.2 Количественные метрики
- **Время создания**: От идеи до готового продукта < 2 дней
- **Количество идей**: > 12 идей продуктов в месяц
- **Успешность запуска**: > 80% продуктов доходят до запуска
- **Конверсия в премиум**: > 5% бесплатных пользователей становятся платными

```
Fitness = 0.4 * Implementation_Simplicity + 0.3 * Market_Size + 0.2 * Freemium_Potential + 0.1 * Launch_Speed
```
