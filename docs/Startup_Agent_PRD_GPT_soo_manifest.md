МАНИФЕСТ СОЛО-СТАРТАПЕРА
0) Норт-стар

Каждые 7 дней — новый крошечный продукт (или существенный апдейт), от PRD до лендинга и первого трафика.
Артефакты недели: PRD (строго по схеме) → лендинг → 1 видео (вертикаль) → 1 пост (LinkedIn/сообщество) → минимальная воронка оплаты/лидов.

1) Принципы

Одна боль → одна функция → один экран. Чем меньше, тем быстрее фидбек.

Evidence-first. Числа и факты в PRD только с источниками; без источника — не попадает.

Schema over prompt. Структурируй мысль через схемы SGR и чек-листы; ничего «в воздухе».

Эволюционируем процесс, не текст. Улучшаем схемы PRD, порядок шагов и метрики — не «красивость».

WIP=1. Пока текущий PRD не «зелёный», новые идеи — в инбокс.

Ship > Perfect. Выпущенное несовершенно лучше невыпущенного идеального.

Публичные сигналы > мнения. CTR/лиды/конверсии важнее интуиции.

2) Архитектура работы (5D)

Discovery — сбор ниш и слабых мест SERP (снимок топ-10, форумы/реддит, старые гайды).

Decision — скоринг «занимаемости», усилий, монетизации; выбор одной ниши.

Design (PRD) — строгая схема: проблема, ICP/JTBD, 3–5 фич с acceptance, KPI, риски, техтребования.

Delivery — лендинг из PRD, Stripe (если нужно), demo/скринкаст, sitemap/hreflang.

Distribution — короткое видео (вертикаль), пост в LI/Twitter/сообщество, ответы на ветках.

3) Про выбор ниши (S.E.E.D.)

S (Searchability) — серп легко занять: форумы в топ-10, нет свежих биг-медиа, мало видео/брендов.

E (Evidence) — видны реальные вопросы/боли (ссылки на треды).

E (Ease) — реализуемо за 1–2 дня на вашем стеке.

D (Demand) — длинные хвосты и LSI-варианты, простая монетизация (one-time/usage/freemium).

Kill-флаги до начала:
в топ-10 в основном гиганты/энциклопедии; свежие гайды последнего месяца; видеокарточки на первых позициях; «хрупкость» — в симуляции добавь «биг-медиа» и видео → если SERP-скор рушится сильно, не идём.

4) PRD (как должен выглядеть)

Definition of Done (PRD):

Проблема ≥ 30 слов, понятный ICP (сегмент/каналы).

3–5 фич, у каждой acceptance criteria.

3–5 KPI с единицами (daily/weekly/…); цели ≥ 0.

3–5 рисков с планом минимизации.

Техтребования: ≥3 API-эндпоинта /api/..., интеграции, NFR (скорость/стоимость/логирование/бэкапы).

Все цифры/утверждения — с source URL.

Одно ясное UVP и CTA.

Анти-болото: линтер PRD (проверка чисел без источников, валидность KPI, гигиена API), pre-mortem («где сломается»), «shadow-PRD» (альтернативная формулировка боли).

5) Лендинг (минимум)

Один экран: проблема → демо → CTA (кнопка/форма/Stripe).

Тех-SEO: title/OG/json-ld, sitemap, hreflang; грузимся быстро (Astro/статик).

A/B два заголовка (edge-сплит), копим простые события: view → click → signup/checkout.

Док-страница: «examples», «compare» — 2–3 короткие подстраницы для P-SEO.

6) Контент-пак (каждый релиз)

Вертикальное видео 30–45с: HOOK → PROBLEM → DEMO → CTA.

LinkedIn-пост: краткая история (до/после), 1 конкретный пример, 1 мини-диаграмма/код-кусок, CTA.

Community/форум: отвечаем в релевантных тредах; не спам, только по делу.

I18N: EN + 1 локаль (где SERP-зазор больше), hreflang.

7) Монетизация (правило простоты)

Если косты ≈ 0 → бесплатно + email capture.

Если есть издержка (API/модели/хранение) → one-time или usage-based первым делом, затем «микро-подписка».

Stripe с одной позицией цены и минимальным вэбхуком (выдача ключа/лимита).

Апселл — только после первых 20–50 оплат/лидов.

8) Метрики (простые, управляемые)

До релиза:

SERP-скор ≥ 0.6; «robustness-delta» (после симуляции «пришёл гигант») ≥ −0.1.

PRD-линт-скор = 1.0 (нет критических замечаний).

После релиза (первые 7 дней):

CTR на заголовке ≥ 3% (бенч ниши).

≥ 1% signup/lead от уник. визитов (или ≥ 5 лидов/нед).

Если Stripe: ≥ 2–5 оплат (микро-чек).

Портфель:

12 shipped/12 мес (min).

Активные:архив ≥ 1:2; архив — не кладбище, а «банк заготовок».

9) Решения: Kill / Iterate / Double-down

Kill (архив): 2 недели подряд CTR < 70% порога ниши и лид-rate ниже 0.5% → закрыть, записать инсайты.

Iterate: метрики на грани, есть конкретный фидбек по 1 фиче → итерация ≤ 1 день.

Double-down: топ-квартиль CTR, лиды каждую неделю → доп. язык, 2–3 P-SEO страницы, партнёрский пост.

10) Каденс и ритуалы

Неделя (ритм 5×1):

Пн: 5 ниш → 1 победитель (решение по фитнесу).

Вт: PRD v1 (строго по схеме) + линт/пре-морем.

Ср: лендинг + A/B; demo/gif.

Чт: видео + посты; сбор первых сигналов.

Пт: ретро — цифры, решение Kill/Iterate/Double, апдейт схем/чек-листов.

День:

2×90 мин (глубокая работа), 2×45 мин (операционка), один слот «коммуникации/коммьюнити».

Закрыть день: записать 3 факта → 1 решение (куда двигаем схему/процесс).

11) Деньги и риски

Косты: лимит на месяц (хостинг, домены, API, модели). Проверка рентабельности раз в пятницу.

Юридическое: ToS/Privacy минимально, без рискованных интеграций; данные пользователей — храним минимально.

Приватность/лицензии: если используете чужие датасеты/шрифты/иконки — фиксируйте в PRD как риск.

12) Компаундинг (наращивание «мускула»)

Шаблоны повторного использования: лендинг, Stripe, FAQ, видео-скрипт, PRD-чек-лист.

Библиотека доказательств: выдержки из тредов/источники → переиспользуем в будущем.

«Словарь» UVP/заголовков: что сработало/не сработало (по CTR).

Микро-комьюнити: список тем для ответов, календари постов, список реферальных каналов.

13) Анти-выгорание

Рамки успеха недели: shipped = победа, метрики — бонус.

Дефект дня: записать, что помешало (1 строка), как убрать повтор (1 действие).

7-дневные проекты: всё, что длиннее, дробим на инкременты.

14) Инструментальная карта (минимум, без фанатизма)

Хостинг: Cloudflare Pages/Workers (просто, дёшево, быстро).

Оплата: Stripe (один price, один webhook).

Аналитика: Cloudflare Web Analytics/умеренный PostHog.

Таски: один список «СЕГОДНЯ», один «ИНБОКС» идей (Zero-inbox каждую пятницу).

Хранилище инсайтов: заметки/репозиторий PRD, архив артефактов.

15) «12 за 12»: рамка запуска

Каждый месяц: 3 ниши → 1 релиз → 2 недели наблюдения → решение.

Ретроспектива месяца: распределение CTR/конверсий, источники трафика, win-паттерны UVP/CTA.

Честный отчёт самому себе: «что убираю, что стандартизирую, что автоматизирую».

ОДНОСТРАНИЧНАЯ ШПАРГАЛКА (печать и на стену)

Миссия: 1 боль → 1 функция → ship за 7 дней.

Выбор ниши: SERP-скор ≥ 0.6, слабые места: форумы/старые гайды/нет видео/мало брендов.
PRD DoD: проблема (≥30 слов), ICP, 3–5 фич с acceptance, 3–5 KPI, 3–5 рисков, техтребования (≥3 API /api/..., интеграции, NFR), все числа со ссылками.
Лендинг: один экран, демо, CTA, sitemap/hreflang, A/B заголовков.
Контент: 1 вертикальное видео (HOOK→PROBLEM→DEMO→CTA), 1 LI-пост (до/после + пример + CTA).
Метрики 7 дней: CTR ≥ 3%, лид-rate ≥ 1% (или ≥5 лидов), если Stripe — ≥2–5 оплат.
Решения: Kill (две недели ниже порога), Iterate (конкретный фидбек), Double-down (топ-квартиль).
Ритм: Пн ниши → Вт PRD → Ср лендинг → Чт контент → Пт ретро.
Заповеди: Evidence-first, Schema-first, WIP=1, Ship>Perfect.

Дополнительные рабочие практики (кратко)

«Аналоговый» фокус: утро без чатов (до PRD/лендинга).

Три уровня планирования: день (3 outcome), неделя (1 ship), месяц (1 тезисный фокус).

Карта отказов: записывать причины Kill → превращать в проверки в PRD-чек-листе.

Партнёрский пост/видео 1×мес. — обмен трафиком с микро-аудиториями.

Семантические «кластеры» P-SEO: 2–3 подкластера на нишу (how-to, compare, examples).

Email-хук: бесплатный мини-репорт/шаблон по теме (0→1 подписчики, не пытаться «вести рассылку», пока нет 100+).

«Не код» днём, «код» вечером (или наоборот): чёткое разделение, чтобы не прыгать между задачами.
