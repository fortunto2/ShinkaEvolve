ЕДИНЫЙ МАНИФЕСТ СОЛО-ФАУНДЕРА

SGR × ShinkaEvolve; Жирар × Тиль × Талеб; фабрика микро-продуктов

0) Кредо (основы мышления)

Не где все — а где я единственный. Жирар/Тиль: выбираю поле, где могу стать №1 хотя бы в микро-нишe.

«Ноль-к-одному», а не «я тоже». Тиль: делаю не копию, а маленькую уникальную вещь.

Антихрупкость. Талеб: удары усиливают — строю процесс, который крепнет от обратной связи.

1) Магистральная стратегия

Микрополе → локальная монополия → масштаб через партнёров.

Barbell-подход: 80% — устойчивое ядро (повторяемые схемы/лендинги/чек-листы), 20% — дерзкие опционы.

Скорость > совершенство: сначала ценность и проверка спроса, затем автоматизация.

2) Операционная система (как живёт фабрика)
2.1 Контур 5D

Discovery → Decision → Design (PRD) → Delivery (лендинг/демо) → Distribution (контент/каналы).
Главный артефакт каждого цикла — строгий PRD для разработки и маркетинга.

2.2 Эволюционный слой (ShinkaEvolve поверх SGR)

Level 1: Background Evolution. Ночью система ищет ниши, стресс-тестит SERP, предлагает PRD-шаблоны.

Level 2: Daily Decisions (30 мин). Утром выбираю из топ-кандидатов, даю GO/NO-GO, добавляю фидбек.

Level 3: Weekly/bi-weekly Ship. Выпускаю один микро-продукт или существенный апдейт.

Критические инструменты: novelty-фильтр по схеме, robustness-симуляция SERP, evidence-линтер.
SGR задаёт рельсы (схемы/валидации), Shinka — улучшает сами схемы и порядок шагов.

3) Выбор ниши: S.E.E.D.

S — Searchability (занимаемость): форумы/Reddit в топ-10, мало свежих гигантов/видео/сильных брендов.

E — Evidence (доказательства): реальные вопросы/боли со ссылками.

E — Ease (лёгкость): MVP делается за 1–2 дня на моём стеке.

D — Demand (спрос): длинные хвосты/LSI, понятный сценарий монетизации.

Kill-флаги до начала: топ-10 — медиагиганты/энциклопедии; свежие гайды <60 дней; видео-блоки на первых позициях; robustness-симуляция показывает резкое падение SERP-скора при «вбросе» гиганта.

4) Обязательная валидация (День 0): Fake-Door Test

Лендинг-заглушка (2 часа), $20 на малые объявления/трафик.

KILL: <10 кликов на CTA за $20. BUILD: если интерес подтверждён.

Цель — дешевле всего проверить «есть ли кислород».

5) PRD: Definition of Done (строго, проверяемо)

Проблема ≥ 30 слов (кто страдает, когда, почему сейчас).

ICP/JTBD: сегмент + 2–3 «работы» пользователя.

3–5 фич, у каждой — acceptance criteria (детально и измеримо).

3–5 KPI с единицами (daily/weekly/…); целевые значения ≥ 0.

3–5 рисков + план минимизации (право/данные/каналы/зависимости).

Техтребования: ≥3 API /api/..., интеграции, NFR (скорость, логирование, бэкапы, лимиты).

Evidence-first: любые числа/утверждения — со source URL (встроенные поля источников).

Контроль качества PRD

Evidence-линтер: ловит числа без ссылок, некорректные KPI, неаккуратные эндпоинты.

Pre-mortem (контр-PRD): где сломается и как это заметим.

Shadow-PRD: альтернативная формулировка боли/UVP для A/B.

6) Delivery: лендинг/демо без тяжёлой разработки

Один экран: ПРОБЛЕМА → ДЕМО → CTA.

SEO-минимум: title/OG/JSON-LD, sitemap, hreflang.

A/B заголовков (edge-сплит), события: view → click → signup/checkout.

P-SEO кластеры: /examples, /compare (2–3 подстраницы, короткие и конкретные).

7) Distribution: минимальный контент-пак

Вертикальное видео 30–45 с: HOOK → PROBLEM → DEMO → CTA.

LinkedIn-пост: история «до/после», 1 конкретный пример/мини-график, CTA.

Коммьюнити: ответы по делу в релевантных ветках.

I18N: EN + 1 локаль, где «SERP-зазор» выше; корректный hreflang.

8) Деньги без перегрева

Косты ≈ 0: бесплатно + email capture.

Есть издержка: сначала one-time/usage-based, позже — «микро-подписка».

Один Stripe price и один webhook; апселл — после 20–50 оплат/лидов.

Девиз: денежный поток > хайп.

9) Антихрупкая архитектура (Талеб)

Модульность: любой блок заменяем за 1–2 недели.

Нет SPOF: один клиент, канал или вендор — табу.

Опциональность: 3–5 маленьких ставок с асимметрией «малый риск → большой апсайд».

Обратимость: спорные решения — только через обратимые эксперименты.

10) Миметическая гигиена (Жирар)

Фильтр желаний: «Это моё или навязанное рынком?»

Избегаю «красных океанов»; иду туда, куда толпа придёт через 12–24 месяца.

11) Захват ниши (Тиль)

Единственная фича-ядро даёт 80% ценности.

Гипер-ниша, где без меня «никак».

Concierge-подход: некритичное — вручную до первых денег.

Эффект плотины: 1–2 кейса → публичные результаты → вход к следующей десятке.

12) Метрики (реальные и управляемые)

North Star: количество завершённых «ценностных исходов»/неделю на активного клиента.

Еженедельные:

Активация L7/L14, удержание когорт.

Payback Period (месяцы до окупаемости клиента).

Валовая маржа, cost-to-serve (ручной/авто %).

Пайплайн партнёров: новые → переговоры → пилот → платят.

активных экспериментов и их ROE (result-over-effort).

Относительные метрики по категории:
relative_ctr = CTR / CTR_бенчмарк_ниши, relative_conv = Conv / Conv_бенчмарк_ниши; итог = среднее.
Сравниваю себя с бенчмарком ниши, а не с произвольной «нормой».

13) Решения: Kill / Iterate / Scale

Неделя 1 (Fake-door): <10 кликов интереса → KILL.

Неделя 2: signups = 0 → KILL; 1–4 → ITERATE; ≥5 → DOUBLE-DOWN.

Неделя 3+: рост signups WoW: <0 → ARCHIVE; > +50% → SCALE (новая локаль, партнёрство, P-SEO).

14) Каденс и ритуалы (реалистично)

Спринт-форматы:

14-дневный: неделя research/PRD/прототип, неделя запуск/трафик; или

Параллельные треки: один продукт в запуске, следующий в research.

Ритуал недели:

Пн (90 мин): выбрать 1–2 решающих шага недели, заморозить остальное.

Ср (30 мин): чек-поинт — отрезать всё, что не двигает North Star.

Пт (60 мин): разбор — что стало антихрупче? что «сломать безопасно», чтобы усилиться.

День: 2×90 мин глубокой работы, 2×45 мин операционки, 1 слот коммьюнити.

15) Масштаб через чужие ресурсы

Партнёры с выходом на мою ЦА (платформы, агентства, лидеры ниши).

Интеграции вместо тяжёлого собственного маркетинга.

Кейсы как валюта: 2–3 измеримых результата открывают двери.

16) Красные флаги (режу немедленно)

«Ещё одна» фича «как у всех».

Один клиент >30% выручки; один канал лидов >60%.

Vanity-метрики (лайки/клики) без влияния на выручку/удержание.

Релиз, который нельзя откатить за день.

17) План на 3–6 месяцев

Мес 0–1: сузиться до гипер-ниши, релиз ядра, 1–2 кейса (ручной довоз).

Мес 2–3: партнёрские интеграции, white-label, 2–3 истории успеха, пилоты с предоплатой.

Мес 4–6: закрытая бета по инвайтам, барьеры входа (интеграции/данные/воркфлоу), автоматизирую лишь то, что уже даёт выручку.

18) Коммуникации и «skin in the game»

Обещаю только то, что могу выполнить руками.

Пилоты — с KPI и дедлайнами; бонус за перевыполнение, штраф-клаузула за срыв с моей стороны.

Ошибки — публичный пост-мортем → превращаются в фичу или регламент.

19) Личная присяга

Я выбираю тишину будущих трендов, а не шум сегодняшней толпы.
Я строю систему, которая крепнет от ударов.
Я зарабатываю раньше, чем автоматизирую.
Я режу всё лишнее, кроме ценности.
Я измеряю реальность, а не ожидания.
Я сохраняю право быстро передумать.

20) Одностраничная шпаргалка (повесь на стену)

Миссия: 1 боль → 1 функция → ship (14-дневный или параллельный ритм).

Ниша: SERP-скор ≥ 0.6; слабые места: форумы/старые гайды/нет видео/мало брендов; robustness-симуляция — ок.

День 0: Fake-door за $20 → <10 кликов = KILL.

PRD DoD: проблема ≥ 30 слов; ICP/JTBD; 3–5 фич с acceptance; 3–5 KPI; 3–5 рисков; ≥3 API /api/...; NFR; все числа — со ссылками.

Лендинг: один экран, демо, CTA, A/B заголовков, hreflang.

Контент: 1 вертикальное видео; 1 LinkedIn-пост; 1–2 ответа в релевантных тредах.

Метрики 7 дней: относит. CTR/Conv ≥ 1.0× бенчмарка ниши; если Stripe — ≥ 2–5 оплат.

Решение: Kill / Iterate / Scale по правилам §13.

Заповеди: Evidence-first, Schema-first, WIP=1, Ship>Perfect, Антихрупкость.
