Готовые конвертеры / движки

ar5iv — официальный арXivLabs-проект: конвертит TeX→HTML5 через LaTeXML; есть публичный сайт и даже датасет HTML версий (до конца июля 2025). Хорош для получения чистого HTML с формулами/ссылками. 
ar5iv
+1

LaTeXML — базовый конвертер LaTeX→(XML→)HTML/MathML/JATS; именно он стоит у arXiv/ar5iv. 
math.nist.gov

GROBID — парсинг научных PDF в TEI XML с разбором метаданных/цитат; пригодится как fallback по PDF (когда .tex нет). 
grobid.readthedocs.io
+1

Docling (IBM) — свежая опенсорс-библиотека «под LLM», умеет PDF→структурированный текст/Markdown, интегрируется в пайплайны. 
GitHub

MarkItDown (Microsoft) — универсальный файл→Markdown «для LLM», сохраняет заголовки/таблицы/списки. Для научных PDF менее точен, чем LaTeXML по формулам, но удобен как общий слой. 
GitHub

pdf4llm / pdf2markdown4llm / Marker — молодые утилиты прямо с фокусом «LLM-ready Markdown» и чанкингом по страницам. Можно тестить как быструю базулайн-конверсию из PDF.

Ниши/углы, где можно выделиться

LLM-friendly Markdown (не просто HTML-копия)

Чистая иерархия (#, ##, ###), стабильные якоря для секций/теорем/рисунков, конвертация \ref/\cite в кликабельные ссылки и bidirectional cross-links.

Формулы как $...$/$$...$$ + совместимость с MathJax/KaTeX; для нумерованных уравнений — автогенерация тэгов и якорей. 
Pandoc
+1

Семантическое разметивание под чанкинг

Чанки «по смыслу»: абзац/теорема/лемма/доказательство/figure/table, а не тупо N токенов.

Выдача «микро-MD» блоками с stable IDs — идеально для RAG-сниппетов и обновлений.

Фигуры/таблицы/код

Вытаскивать подписи, alt-текст, артефакты таблиц → pipe в Markdown-таблицы; по возможности делать OCR графиков и код-блоков (fenced ```lang). Docling/Unstructured тут полезны как доп-слой. 
GitHub

Цитаты и библиография

Нормализация ссылок в CSL JSON/BibTeX, создание обратных ссылок из текста на список литературы (и наоборот). GROBID умеет вытягивать biblio-структуру. 
grobid.readthedocs.io

Двухрежимный ingestion

TeX-путь (золото-стандарт): скачали .tex → LaTeXML → HTML → Markdown (GFM) → чанки/эмбеддинги.

PDF-fallback: Docling/pdf4llm/Unstructured → Markdown → дообогащение (заголовки/формулы).

MVP (быстрый запуск)

Fetch: arXiv API → метаданные + ссылки; при наличии HTML-версии — стягиваем ar5iv-HTML как эталон.

Почему сейчас можно «зайти»

Сам arXiv уже даёт HTML, но это не LLM-оптимизация: нет идеального чанкинга, стабильных якорей, двунаправленных ссылок и нормализованных библиографий — здесь можно дать «Markdown-для-моделей», а не просто «HTML-для-людей». 
blog.arxiv.org

Разрозненные инструменты (Docling/MarkItDown/pdf4llm) — ок по PDF, но без науки-специфики (теоремы/ссылки/eq-refs). Ты можешь собрать специализированный конвейер arXiv-papers→LLM-MD и стать «самым чистым» источником.

Мини-сравнение подходов

TeX→LaTeXML→HTML→MD — лучшая семантика и формулы, требует доступа к исходникам/устойчивого постпроцессинга. 
math.nist.gov

HTML (ar5iv/официальный)→MD — быстро и стабильно, чуть меньше контроля над гибридными конструкциями/макросами. 
ar5iv

PDF→MD (Docling/pdf4llm/Unstructured) — покрытие 100%, но ниже точность формул/кросс-рефов; годится как fallback.
